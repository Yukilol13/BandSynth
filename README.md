# BandSynth · 采样合成器工作站

输入一段采样 → 用键盘演奏出指定音高；输入一份「琴谱」JSON → 自动生成并导出录制好的伴奏。
纯前端实现，零安装，**双击 `index.html` 即可用**。

开源仓库：<https://github.com/Yukilol13/BandSynth> ｜ 许可：[MIT](LICENSE)

---

## 快速开始

1. 用 Chrome / Edge 打开 `index.html`（推荐 Chrome，音频兼容性最好）
2. 点击页面任意处启动音频引擎
3. 默认已装载三个内置音色（钢琴 + 贝斯 + 原声吉他），按电脑键盘 `Z S X D C V G B…` 即可演奏
4. 切到「编曲」页选示例乐谱或直接编排，点 ▶ 试听；切到「渲染导出」页一键导出 WAV

> 需要加载自己的采样：选中左侧声部 → 「采样」面板 → 选择文件（支持手机录音、视频、微信传输视频）

## 一、采样格式支持

| 类别 | 格式 | 状态 |
|---|---|---|
| 手机录音 | m4a / aac / mp3 / wav / flac / ogg / opus | 直接可用 |
| 视频文件 | mp4 / mov / m4v / webm | 直接可用（自动只取音轨，忽略画面） |
| 微信传输视频 | mp4 (H.264 + AAC) | 直接可用 |
| 微信语音消息 | amr / silk | **需转码**（私有格式，浏览器无法解码） |
| 其他容器 | mkv / wma / aiff | 建议转 WAV |

解码走浏览器原生 `decodeAudioData`，WAV 另有自研解析器兜底（兼容部分 `decodeAudioData` 不认的 WAV 变体）。

**转码命令**（装好 ffmpeg 后）：

```bash
# 微信语音
ffmpeg -i voice.amr -ar 44100 -ac 2 out.wav

# 任意视频抽音轨
ffmpeg -i clip.mp4 -vn -ar 44100 -ac 2 out.wav

# 转成体积更小的 m4a
ffmpeg -i clip.mp4 -vn -c:a aac -b:a 192k out.m4a
```

装载后会显示**可交互的波形编辑器**，可直接试听与裁剪（见下节）。

## 二、采样试听与裁剪（含缩放）

选中声部 → 「采样」面板，装载文件后自动进入波形编辑器。

| **全览 / 贴合选区** | 复位视图 / 缩放到刚好包含选区 |

| 拖动波形左右边缘的青色手柄 | 调整选区起点 / 终点 |

| 循环 | 循环播放（配合「试听选区」可反复听一段） |

| 试听速度 ½× / 原速 / 2× | 慢放查细节，快放查整体 |

下方实时显示起点、终点、选区长度（毫秒级精度）。

### 裁剪动作

| 按钮 | 作用 |
|---|---|
| **物理裁剪** | 把选区真正切出来，丢弃区间外的声音（不可撤销，减小后续计算量） |
| **全览** | 恢复完整采样并把视图复位 |
| **裁当前视图** | 只保留当前放大后可见的区间（缩放后很实用） |
| **对齐零交叉** | 起点吸附到最近的零交叉点，消除起音爆音 |
| **淡入淡出** | 给选区加 5ms 淡入淡出，消除边界咔哒声 |

原有的「裁剪静音 / 归一化 / 转单声道」按钮仍在。

> 裁剪默认是**区间裁剪**（只改 `startSec`/`endSec`，零拷贝、可反复调）；
> 只有点「物理裁剪」才真正切数据。锁时长变调的缓存会在裁剪后自动失效。

### 音频解码链路

```
File → FileReader → ArrayBuffer
        ├─ .wav  → BS.wav.decode(ab)   （自研解析器，core.js；兼容浏览器不认的 WAV 变体）
        └─ 其他  → ctx.decodeAudioData  （浏览器原生）
```

⚠️ **WAV 解析器在 `BS.wav` 上，不在 `BS.loader.wav`** ——
命名空间写错会得到 `undefined.decode`，所有 WAV 导入直接失败。
自研解析失败或不可用时会**自动退回** `decodeAudioData`，不会整条路断掉。

`BS.wav.decode(ab)` 返回 `{ channels: Float32Array[], sampleRate, frames }`，
支持 8/16/24/32bit 整数 PCM 与 32/64bit 浮点。

### 「裁剪静音」的判定逻辑（自适应阈值）

`BS.loader.trimSilence()` **不用固定 dB 阈值** —— 固定阈值对真实素材会失效：

| 素材类型 | 固定 -48dB 的表现 |
|---|---|
| 数字静音 | ✅ 正常 |
| **渐入/渐弱**（人声、乐器、猫叫） | ❌ 开头就高于阈值 → 一帧都不裁 |
| **带底噪录音** | ❌ 底噪高于阈值 → 一帧都不裁 |

现在的算法：

1. **噪声基底** = 窗口峰值的 **10% 低分位数**（不是首尾区峰值 ——
   渐入素材的「首区峰值」本身就是信号）
2. **主阈值** = `全局峰值 × 10^(-35/20)`（**峰值相对值**）
3. **噪声下限**：仅当噪声基底 ≤ **-60dBFS**（判定为「真有静音区」）时，
   才要求阈值 ≥ `噪声基底 × 10^(12/20)`
4. **边界精确到样本**：窗口粗定位后逐样本回退/前进，另留 2ms 余量保住起音与渐弱尾
5. **淡入淡出 3ms**，消除硬切爆音

返回 `{ buffer, startSec, endSec, peak, noiseFloor, thresh, hasRealSilence }`，
UI 会显示实际用了什么阈值。

可调参数（`opts`）：`floorDb`（默认 -35）、`marginDb`（12）、
`noisePercentile`（0.10）、`silenceFloorDb`（-60）、`guardMs`（2）、`fadeMs`（3）。

> 判据必须用**绝对量纲**（-60dBFS），不要用「比峰值低多少 dB」——
> 后者会把渐入素材误判成「有静音区」，阈值被抬高后会把大半个素材裁掉。

### 试听通路

试听走**独立通路**（`source → gain → 主控`），**不经过声部的 ADSR 与滤波**——
否则包络会把采样包得面目全非，听不出素材本身的好坏。
音量与声部音量、主控音量互相独立。

## 三、内置音色

24 种音色全部由代码实时合成（`src/tone.js`），不依赖任何采样文件。

### 鼓组（12 种）
底鼓、军鼓、拍手、闭镲、开镲、低/中/高嗵、叮镲、碎音镲、边击、沙锤 —— 物理建模（噪声 + 包络 + 带通）。

### 乐音（12 种）

| 音色 | 模式 | 合成方式 | 特点 |
|---|---|---|---|
| 贝斯 | gate | 加法合成 | 基频 + 点缀亚音 + 低通压高频 |
| 暖垫 | loop | 加法合成 | 慢起慢落 + 微失谐拍频 |
| 电钢 | gate | 加法合成 | Rhodes：基频 + 三次谐波钟音 + 拍频 |
| **钢琴** | oneshot | 加法合成 | 奇次谐波为主 + 琴槌噪声，秒级指数衰减 |
| 弦乐 | loop | 锯齿+低通 | 双声部微失谐，慢起振 |
| 风琴 | loop | 音栓式 | 各次谐波独立电平 + 合唱失谐 |
| 主音 | gate | 加法合成 | 圆润合成主音（非方波） |
| 钟琴 | oneshot | **非谐分音** | 2.76 / 5.40 / 8.93 倍频（真实钟就是这样） |
| 人声垫 | loop | 共振峰合成 | 元音 /a/ 的共振峰加权 |
| 拨弦 | oneshot | Karplus-Strong | 通用拨弦 |
| **原声吉他** | oneshot | 加法合成 + 拨弦包络 | 基频最强 + 2~6 次递减 + 琴体共振 + 拨片噪声 |
| **电吉他** | oneshot | 加法合成 + 非对称削波 | 过载音色，高次泛音延伸更远 |

### 设计要点：基频必须真实

采样机靠 `playbackRate` 变调（ratio = 2^((note-root)/12)），所以**采样里存的必须是 rootNote 对应的真实音高**。

早期版本用 `ph += 1/dur`（dur 同时当时长与周期），导致基频只有 **0.5Hz** —— 一个周期占满 2 秒。在 rootNote 触发时播出 0.5Hz 次声，升八度是 1Hz，降八度完全不可闻；加上波形在时域上几乎是条直线，任何非整数周期叠加都产生拍频与超幅削波 → **方波味**。

现在按 `f0 = 440 × 2^((root-69)/12)` 合成，循环类时长对齐整数周期（`alignCycles`），实测基频误差 ≤ 1.8%。

### 包络两种衰减

| 参数 | 含义 | 适用 |
|---|---|---|
| `tau` | 指数衰减时间常数（秒） | 拨弦、钢琴 —— 需要快速衰减 |
| `decay` | 每周期衰减系数 | 钟、铃 —— 长延音 |

曾用 `decay` 做原声吉他，实测包络 20ms 段 RMS 从 57 几乎不降到 50（听着是"持续嗡"而非拨弦），改为 `tau` 后正常衰减（56→34）。

### 频谱验证

`node test-tone.js` 用 FFT 实测每个音色的基频、谐波列、循环边界跳变、次声污染，而非只检查"能否生成"：

- 12 个乐音基频误差 ≤ 1.8%，f0 处能量均 ≥ 10%
- 循环类音色边界跳变 < 35% RMS
- 所有音色首样本接近 0（无爆音）、峰值 ≤ 1.0（无超幅）
- 吉他区分：电吉他 12 次谐波 3.0% vs 原声 0.0%（过载泛音延伸更远）；原声吉他 2 次谐波 40.2% vs 电吉他 17.9%（木质共鸣）
- 变调后（升纯五度）基频仍成立

## 四、鼓组（独立演奏页）

顶部第 2 个页签。**鼓组走的是与合成器完全独立的逻辑**：

| | 合成器声部 | 鼓组声部 |
|---|---|---|
| 触发 | `noteOn(音高)` → 算 playbackRate 变调 | `drumId` → 直连声部 |
| 音高 | 关键参数 | **无意义**（底鼓永远是底鼓） |
| 键盘跟随 | `keyTrack=true` | `keyTrack=false`，ratio 恒为 1 |

这不是偷懒——采样器靠 `playbackRate` 变调，鼓没有音高概念。
若硬塞进音高体系，用户改音高时鼓跟着变调就完全错了。因此鼓位用 `drumId` 直连声部。

### 声部结构：鼓组是**独立通道**，完全不碰合成器声部

鼓组**不是** `engine.parts` 里的任何一个 Part，而是独立的 `BS.DrumRack`
（`src/drum-rack.js`）：

```
BS.Engine
  ├─ parts[]          ← 只有合成器声部（Part：音高/变调/滤波/包络）
  └─ DrumRack         ← 鼓组，独立音频通路
       ├─ out → pan → engine.master
       ├─ revSend / dlySend（独立混响/延迟送出）
       └─ drums { kick: {buffer,volume,filter,amp}, snare: {...}, ... }
```

这样设计的根本原因：

| | 合成器声部（Part） | 鼓组（DrumRack） |
|---|---|---|
| 触发 | `noteOn(音高)` → 算 playbackRate 变调 | `hit(drumId)` → 直接放对应 buffer |
| 标识 | MIDI 音高 | 鼓位 id（kick/snare/…） |
| 音高 | 核心参数 | **完全无关**（鼓没有音高概念）|
| 所在位置 | `engine.parts[]` | **完全独立** |

带来的直接好处：
- **声部列表里看不到鼓**，不会出现「选到鼓组却用合成器音高去触发」
- 鼓组不占声部槽，加轨时不会被挤满
- 混音/音量/声像/混响在鼓组通道上一次调好
- 琴谱里鼓轨由 `role:'drum'` 标记，`part` 为 -1（不占索引），走独立通道
- 引擎声部数实测 **16 → 2**（12 个鼓全走通道后）

每面鼓的 buffer 由自己的音色 id 生成并**独立保存**，
所以敲底鼓永远是底鼓音色、敲军鼓永远是军鼓音色，绝不会串。

### 界面

12 面鼓按真实鼓组摆放（鼓手视角）：镲片在上排、嗵鼓右上、军鼓中左、底鼓居中最大。

- **点击鼓面敲击**，敲击位置越靠中心力度越大（真实鼓的 feel：鼓心 100%、鼓边约 62%）
- **键盘映射**：`空格` 底鼓 · `S` 军鼓 · `D` 拍手 · `F` 边击 · `J` 闭镲 · `K` 开镲
  · `Q/W/E` 低/中/高嗵 · `R` 叮镲 · `T` 碎音镲 · `G` 沙锤
- 首次进入点「生成鼓组声部」，会自动创建 12 个声部（复用空槽，不会无限膨胀）
- 敲击时鼓面高亮 + 发光，光晕强度随力度变化

### 鼓的「轨」在琴谱里怎么表示

鼓轨的音符 `pitch` 用**固定 MIDI 音高**标识是哪个鼓（36=底鼓、38=军鼓、42=闭镲…），
导入谱面时按这套音高自动识别为鼓轨。判据是**该轨全部音符都落在鼓音高集合内**——
只要有一个乐音就判为旋律轨，不会误伤。

## 五、工程保存与加载

右侧「工程」区块。工程文件（`.bsproj.json`）包含：

- 全部声部的完整参数（滤波器、包络、变调算法…）+ 采样库 ID 引用
- 已导入的曲谱（内嵌完整 JSON）
- 主控设置（主音量、驱动、混响类型）
- 演奏设置（八度、力度、当前声部、跟随模式）
- 鼓组映射（哪个鼓位用哪个声部）

| 按钮 | 作用 |
|---|---|
| **保存工程** | 导出 `.bsproj.json` 文件 |
| **加载工程** | 从文件恢复 |
| **快速存档** | 存到浏览器本地（localStorage），下次一键取用 |
| **读取存档** | 读取快速存档 |

采样**不存进工程文件**（体积太大），只存 ID 引用。若引用的采样已被删除，
加载时会保留全部参数并提示重新装载，不会静默丢失。

加载工程会清空现有声部后重建，因此工程文件是完整的现场快照。

## 六、键盘：一字排开键位 + 仲裁

### 键盘角色隔离（重要）

`BS.Keyboard` 有两种角色，**只有演奏台的键盘能占用键盘通道**：

| 角色 | 用途 | 是否注册到仲裁器 |
|---|---|---|
| `perform` | 演奏台键盘 | ✅ 注册 synth 通道 |
| `display` | 只显示、不发声的琴键 | ❌ **不注册** |

> 早期所有键盘实例都注册 synth handler，只读琴键一建立
> 就把演奏台的 handler 顶掉 → **演奏页按键全哑，而鼓组正常**
> （鼓组走独立通道所以不受影响）。现在用 `role` 彻底隔离。

同理，`Keyboard.destroy()` 只有 `perform` 角色才会清空通道。

### 键盘仲裁器（解决所有冲突）

整个应用**只有一个** keydown/keyup 入口（`BS.keyArb`），按键按上下文
**只分发给一个消费者**：

| 上下文 | 分发给 | 说明 |
|---|---|---|
| 演奏页 | **只有合成器** | 鼓键不生效 → 不会出现「鼓和键盘一起响」|
| 鼓组页 | **只有鼓组** | 合成器键不生效 |
| 编曲页 | 录制器（仅录制中）| |
| 其它页 | 无 | 只剩全局快捷键 |

**空格的归属按页签裁决**：
- 鼓组页 → 底鼓
- 其它页 → 播放/暂停

全局快捷键（Esc 停止、←→ 换音域）优先级最高，永远不会被乐器键抢走。

冲突自检：`BS.keyArb.checkConflicts()` 返回 `{ errors, notes }`，
实测 **0 处严重冲突**。

### 键位表（一字排开 · 37 键）

全应用只用一种键位：**C 一字排开**（`src/keymodes.js`，`KeyModes.current = 'C'`）。
不做物理键盘仿真，只求好按、音域宽 —— 一整排白键 + 一整排黑键：

| 键组 | 键位 | 音高 | 键数 |
|---|---|---|---|
| 白键 | `Q W E R T Y U I O P [ ]` `Z X C V B N M , . /` | C D E F G A B C · A B C D E F G A B C | 22 |
| 黑键 | `2 3 5 6 7 9 0 =` `A S F G J K L` | C# D# F# G# A# ×3 | 15 |

合计 **37 键**，从**当前音域最低的 C** 起连续三个八度（跨度 36 个半音），无缺口、零碰撞；
音域变化时整表平移（`←` `→`）。

黑键的音程偏移不是随手写的：每个黑键都必须正好是白键序列里缺掉的那个音，
自检 `BS.keymodes.auditLineMap()` 会校验这一点。

> 早期版本还有「音高直通」与「左右手分工（根音 / 级数）」两套键位，代码仍留在
> `src/keymodes.js` 与 `src/keyboard.js` 里，但界面已不再提供切换，全应用固定用上面这一套。

### 音域切换

| 键 | 作用 |
|---|---|
| `←` / `→` | **切换音域**（唯一方式，整表随之平移）|
| `[` / `]` | 演奏键（不是快捷键） |
| `空格` | 播放/暂停（鼓组页为底鼓）|
| `Esc` | 全部停止 |

键盘下方的说明面板会实时显示当前音域的覆盖范围。

## 七、单音色演奏

演奏台默认**只响当前选中的音色**（工具栏「当前音色」有显示）。

原因：若所有非静音声部齐发，切换音色时听到的是叠加结果，
根本分辨不出自己调的是哪一个。

勾选「跟随模式」改为响最后一个声部，方便配着伴奏即兴。
切换声部时会自动停掉正在响的音，避免两个音色叠着响。

## 八、音量控制

分三层，从素材到最终输出：

| 层级 | 位置 | 范围 | 说明 |
|---|---|---|---|
| **试听音量** | 波形面板 | −60 ~ +12 dB | 只影响试听，不影响演奏 |
| **采样音量** | 声部参数 | −40 ~ +12 dB | 素材本身的增益，参与发声与离线渲染 |
| **包络音量** | 声部参数 | 0 ~ 2.0 | VCA 峰值，与 ADSR 联动 |
| **主控音量** | 右侧面板 | −60 ~ +12 dB（旋钮）+ 细调滑条 | 总输出 |

主控区还有 **静音** 按钮（一键保留原音量再恢复）和 **取消独奏** 按钮。

所有 dB 显示与线性增益的换算是精确的（`dbToGain`/`gainToDb` 互转误差 < 1e-9）。

## 九、保存采样与音色

### 声部面板的保存区

装载采样后，「采样」面板下方出现保存区：

| 控件 | 作用 |
|---|---|
| 名称输入框 | 给这个音色起名（保存/导出都用它） |
| **存入采样库** | 存进浏览器本地，下次直接调用。再次点击变为「更新采样库」 |
| **导出 WAV** | 导出成音频文件，可给 DAW 用 |
| **存为预设** | 保存声部全套参数（滤波器、包络、变调算法等） |

导出选项：**仅导出选区** / **归一化** / **5ms 淡化**。

### 采样处理（降噪 / 信噪比）

声部编辑器里的「采样处理（降噪 / 信噪比）」面板，直接处理**当前声部的采样**（破坏性，可撤销一次）。

面板顶部实时显示读数：**峰值 / 噪声基底 / 信噪比**，处理后还会显示信噪比的增量（`+29.6 dB` 这种）。

| 控件 | 作用 |
|---|---|
| **去直流** | 减掉直流偏置。直流会让滤波工作点偏移，也会让噪声门失效 |
| **去工频** | 50 / 60Hz 陷波（含谐波），去空调声、电流嗡声 |
| **去咔哒** | 修掉削波 / 插值造成的孤立高电平尖峰 |
| **去隆隆** | 高通滤波，去低频隆隆声（手风琴、风吹麦穗） |
| **噪声门** | 低于门限的部分压掉：音符之间的底噪直接消失（门限按**相对峰值**给，不同素材不用分别调） |
| **谱减降噪** | STFT 谱减，最有效的一档：先从最安静的若干帧估噪声谱，再逐帧减掉 |
| **归一化** | 把有效电平提上去（峰值或 RMS 目标），降噪后顺手补回音量 |
| **一键降噪** | 去直流 → 去咔哒 → 去工频 → 谱减 → 噪声门 → 归一化 |
| **撤销** | 还原到处理前的采样 |

旋钮：**降噪强度**（谱减的过减因子，0~3）/ **门限**（噪声门，−60~−10 dB 相对峰值）/ **归一化目标**（−40~−6 dBFS）。

谱减用三个细节压住「音乐噪声」：过减因子（减得比估计的噪声更多一点）、谱地板（保留一点点底噪）、增益跨频率平滑（相邻频点增益拉平）。

> 降噪是把噪声基底压下去来提高信噪比，强度过大会连素材本身的泛音一起削掉 —— 先用默认强度试听，再决定要不要加。

### 导出的内容

导出的是**你实际听到的声音**，不是 buffer 原始数据，依次应用：

1. 选区裁剪（startSec / endSec）
2. 反向（若开启）
3. 采样音量（sampleGain）
4. 归一化（可选，峰值对齐 0.98）
5. 淡入淡出（可选，默认 5ms，消除边界咔哒）
6. 削波保护（超 ±1 自动限幅）

文件名会自动带上处理标记，非法字符替换为 `_`：
`我的 采样:v2.wav` → `我的 采样_v2_rev_gain-6.0.wav`

### 采样库页

顶部第 5 个页签。分两块：

**采样库** —— 每条显示名称、时长、采样率、声道、体积。操作：
- **试听** —— 直接播放该采样（不经过声部处理）
- **载入选中声部** —— 把采样装到当前选中的声部
- **新建声部** —— 用它创建一个新声部
- **删除** —— 点击名称可重命名

顶栏「导入文件…」可把外部音频直接入库。

**预设音色** —— 保存了声部全套参数。操作：
- **应用到选中声部** —— 覆盖当前声部参数
- **新建声部** —— 用预设创建新声部
- 点击名称重命名

预设只存参数 + 采样 ID 引用（不重复存音频）。若引用的采样已被删除，加载时会提示并沿用当前采样。

### 存储机制

三级降级，界面顶部会显示当前用的哪一级：

| 后端 | 容量 | 音频格式 | 说明 |
|---|---|---|---|
| **IndexedDB** | 通常数百 GB | Float32 无损 | 首选，Chrome/Edge 正常窗口下可用 |
| **本地存储** | 约 5MB | WAV 16bit 有损 | 降级方案 |
| **仅内存** | — | Float32 无损 | 浏览器禁用持久化时，刷新即失 |

> **为什么强调存储方式**：用 `file://` 直接打开时，部分浏览器会限制大容量存储。
> 若显示「本地存储」，建议改用 Chrome/Edge 的普通窗口打开（把整个文件夹拖进地址栏），
> 即可获得完整容量与无损保存。

保存的采样与预设与浏览器绑定：清除浏览器数据会一并清除，重要素材请导出 WAV 备份。

## 十、变调：两种算法怎么选

这是本软件的核心能力，同一个声部可随时切换：

### 变速变调（varispeed）— 采样机传统方式
直接改播放速率。**零延迟、零计算成本**，音高变化时时长同步变化（升高变短、降低变长）。

- 适合：鼓组、贝斯断奏、一次性音效、需要瞬态速度感的音色
- 优点：响应即时，重复触发不会有延迟
- 缺点：高音区会明显变短

### 锁时长变调（stretch）— WSOLA 波形相似度重叠相加
先做时间伸缩，再用复采样改变音高。**音高任意变化而时长不变**。

- 适合：pad 衬底、持续和弦、需要严格卡时值的音轨、loop 型采样
- 原理：以固定合成步长逐帧输出，每帧在输入中按分析步长前进；为避免叠加产生梳状滤波，每帧在自然延伸位置附近做相似性搜索，找最相似的候选
- **实测音准**（440Hz 正弦，high 档）：升八度误差 0.13%、纯五度 0.40%、半音 0.43%、降八度 0.28%，时长比精确为 1.0000
- 计算在后台分片进行（每片 6ms），**不阻塞 UI 与音频线程**；首次触发某音高时先用变速变调即时出声，结果算好后自动升级
- **编曲页例外：不兜底、先算完再播**。缓存没命中时退回变速变调，音高是对的但**时值会跟着音高变**
  （升八度短一半），同一个 pad 音色在不同音高上长短不一、卡不进小节 —— 听起来就是「时值没锁住」。
  所以编曲起播前会按**本曲实际用到的音高**（不是每 3 个半音粗预热）算完缓存再开始，
  期间状态显示为预备、按键不落谱；进入编曲页时也会在后台预热一次，点音块试听同样会补算

**质量档位**（帧长决定 OLA 相位重建精度）：

| 档位 | 帧长 | 实测音高误差 | 适用 |
|---|---|---|---|
| low | 2048 | ~2% | 快速试听 |
| medium | 4096 | ~2% | 日常使用 |
| high | 8192 | **±0.4%**（约 2–8 音分） | 需要音准的场合 |

> 帧长越长，帧内包含的信号周期越接近整数，OLA 重建误差越小。这是从实测数据反推的设计：440Hz 周期为 100 采样，1024 帧会产生 +17% 的系统性音高偏移，8192 帧降到 ±0.4%。

超过 ±3 个八度（ratio > 7.9 或 < 0.127）自动回退到变速变调。

## 十一、演奏功能（类硬件合成器）

### 声部系统
多声部编组，每声部独立参数：音量、声像、混响/延迟送出、静音、独奏、复音上限（1–32）。
删除/添加声部即时生效。

### 每声部参数
- **采样**：起始点、结束点、原声高（决定键盘哪个键对应原速）、移调（±24 半音）、微调（±100 音分）

### 原声高：装采样时自动识别，不是硬编码 C4

「原声高」= 这段采样本身的音高，按这个键播放才是原速（`playbackRate = 1`）。
早期装载后一律填 **C4** —— 那只是默认值、不是分析结果：录一个 A2 的贝斯，按 C4 会加速（音高也一起偏）。

现在装载采样（文件 / 采样库 / 新建声部）后会跑一次检测：

```
降采样到 11k 单声道 → 挑能量最高的若干帧 → 每帧 CMNDF（YIN 的累积均值归一化差分）
→ 第一个可信谷得基频 → 半音域加权中位数 → 落到最近的平均律音高
```

- 置信度 ≥ 50% 才写入，并提示「识别为 A3（实测 221.3Hz，偏差 +10 音分）」
- 鼓 / 噪声 / 和弦 / 混响很重的素材**不会瞎猜**：保持原值并如实提示，可用「识别原声高」按钮或直接转「原声高」旋钮手动改
- 改原声高会**作废锁时长变调的缓存**（缓存按 `bufferId + 音高比` 存，根音一变整批失效）

> 检测只对「单音、有明确基频」的素材可信。整套鼓循环该用鼓组通道（不走音高体系），
> 而不是塞进合成器声部再猜音高。
- **播放模式**：单次 / 门控 / 循环
- **变调算法**：变速变调 / 锁时长变调
- **滤波**：7 种类型（LP/HP/BP/陷波/峰化/低架/高架）、对数刻度截止频率、共振、键盘跟随、滤波包络
  —— **BP（带通）给两个频率**：低切（高通边）+ 高切（低通边），各自独立可调。
  单个 Biquad 的 `bandpass` 只有「中心频率 + Q（带宽）」，用户没法分别选保留下限与上限，
  所以 BP 走 **高通 → 低通两级级联**；低切被调到高于高切时引擎会自动拉开，
  键盘跟随与滤波包络对两个边同步生效（包络扫的是整条频带，不是把带宽压窄）
- **包络**：音量 ADSR + 滤波 ADSR
- **第二滤波器**：独立开关，用于叠加塑形
- **音色**：驱动饱和（0–1）、齐奏（1–7 音）、失谐（spread）
- **演奏**：滑音（portamento）、音高跟随开关、力度→音量映射

### 主控与效果器
主音量、总驱动、动态压缩；5 种混响（房间/大厅/金属板/弹簧/教堂）；延迟（时间/反馈/返回）。

### 演奏控制
- 虚拟键盘：鼠标点击与拖动滑奏，纵向位置决定力度（越靠上越轻，模拟真实触键）
- 电脑键盘映射（一字排开 37 键，见「键盘」一节）：

```
白键  Q W E R T Y U I O P [ ] Z X C V B N M , . /   → 从当前音域最低的 C 起连续三个八度
黑键  2 3 5 6 7 9 0 = A S F G J K L               → C# D# F# G# A# ×3
← →   →  音域升降（整表平移）
空格  →  播放 / 暂停
Esc   →  全部停止（含试听）
```

- 走带在**编曲页**（播放 / 停止 / 录制 / 循环 / 速度 / 拍号），顶栏留节拍器与电平表
- 实时显示：小节.拍、播放时间、输出电平表、复音数

### 内置音色（24 种，零采样即可用）
鼓组（12）：底鼓、军鼓、拍手、闭镲、开镲、低/中/高嗵、叮镲、碎音镲、边击、沙锤
乐音（12）：贝斯、暖垫、电钢、钢琴、弦乐、风琴、主音、钟琴、人声垫、拨弦、原声吉他、电吉他

全部由代码合成（鼓组为物理建模，乐音为加法合成 + Karplus-Strong 拨弦），与外部采样走完全相同的通路。

## 十二、琴谱格式（伴奏数据契约）

时间单位是**拍（beat）**，小节线由 `bpm` + 拍号推导，避免冗余的绝对秒数。

### 完整 Schema

```json
{
  "version": 1,
  "name": "我的歌",
  "bpm": 92,
  "timeSignature": [4, 4],
  "swing": 0,
  "loopBars": 8,
  "tracks": [
    {
      "name": "底鼓",
      "part": 0,
      "volume": 0.9,
      "pan": 0,
      "notes": [
        { "beat": 0,   "len": 1,   "pitch": 36, "vel": 1.0 },
        { "beat": 2.5, "len": 0.5, "pitch": 36, "vel": 0.8 }
      ]
    }
  ]
}
```

### 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 曲名 |
| `bpm` | number | 速度，20–400 |
| `timeSignature` | [number, number] | 拍号，如 `[3,4]`；也接受 `"6/8"` 字符串 |
| `swing` | number | 0–0.9，摇摆量（推迟八分反拍） |
| `loopBars` | number | 循环小节数，0 或省略 = 不循环 |
| `tracks` | array | 轨道数组 |

### 轨道字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 轨名 |
| `part` | number | 绑定第几个声部（0 起） |
| `volume` | number | 轨道音量增益 |
| `pan` | number | −1 ~ 1 |
| `muted` / `solo` | bool | 静音 / 独奏 |
| `notes` | array | 音符列表 |

### 音符字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `beat` | number | 起始拍（0 = 曲首），支持小数 |
| `len` | number | 时值（拍） |
| `pitch` | number \| string | MIDI 音高 / 音名 / 和弦，见下 |
| `vel` | number | 力度 0–1，缺省 1 |
| `tie` | bool | 连音，不重新触发 |
| `micro` | number | 微移（秒），用于人性化或抢拍补偿 |
| `mute` | bool | 休止（该音符不发声） |

**简写别名**：`b` = beat，`d` = len，`n` = pitch，`v` = vel（`notes` 本身也可直接写成数组）。

### pitch 的三种写法

```json
{ "pitch": 36 }              // MIDI 数字
{ "pitch": "C2" }            // 音名
{ "pitch": "C" }             // 省略八度 → 默认 C3
{ "pitch": "C3:E3:G3" }      // 和弦 → 自动展开为 3 个音（分隔符 : + | , 均可）
```

### 容错
非法字段不会导致整谱失败：坏 JSON 报错、缺 `tracks` 报错、`len ≤ 0` 修正为 0.25、非法 `pitch` 回退 C3、非法 `beat` 归零，并在导入时提示警告。

## 十三、编曲数据模型与保存格式

编曲页（顶部第 3 个页签，DAW 式横向谱面）的数据是**两层结构**：

```json
{
  "version": 1, "type": "arranger",
  "structure": "track-flat",
  "bpm": 120, "timeSignature": [4, 4], "lengthBars": 16,
  "key": "C", "scale": "major", "grid": 0.0625,
  "tracks": [
    { "name": "旋律", "part": 0, "role": "synth", "volume": 1, "pan": 0,
      "notes": [ { "beat": 0, "len": 4, "pitch": 60, "vel": 0.9 } ] }
  ]
}
```

**每轨一个扁平音符数组**，每个音符自带 `beat`（绝对拍）+ `len`（时长）+ `pitch`。
这个结构天然支持两类编曲需求：

| 需求 | 数据层表现 |
|---|---|
| **和弦** | 同一轨内多个音高共享同一 `beat` |
| **长短音重叠** | 不同 `beat` 的音，时长区间可以交叠 |

### 为什么不用「按小节分片」？

实测 4 轨 × 32 小节 × 512 个音：分片结构 JSON 体积只大 **1.9%**，
却要付出四个代价：

1. **跨小节长音被劈成两半** —— 音高/力度/延音无法表达，直接违背重叠需求
2. 拖动音块跨小节要同时改两处数组
3. 导出前要重新拼回扁平列表
4. 小节数变化不再是「只改显示长度」的简单操作

所以保持 `structure: "track-flat"`，并把这个约定**写进序列化文件**，
防止以后有人误改成分片。

### 工具栏：按功能分三行

编曲页顶部不再是「一长条挤在一起的选项」，而是**一行一类功能**：

| 行 | 内容 |
|---|---|
| ① 播放与视图 | 试听 / 停止 / 录制、撤销 / 重做、循环 / 缩小 / 适配 / 放大、曲式（调性 · 调式 · 速度 · 拍号 · 小节数 · 吸附）、音轨增删、状态条 |
| ② 单小节快速填入 | 和弦库 + 模板 → 「填入本小节」、预备拍、小节选择 / 删除小节 / 全选本轨 / 删除选中 |
| ③ 铺进行 | 和弦进行库 → 「铺进行」、铺进行选项（同时铺鼓组 / 同时铺其它音轨）、提示 |

「单小节填入」与「铺进行」**分成两行**：一个管「这一小节用什么和弦、什么模板」，
一个管「整段进行怎么铺」，混在一行时很容易点错。

### 和弦选择器：级数 + 分类筛选

点顶部标尺的**和弦格**弹出选择器（工具栏的「和弦」下拉则是直接选一个和弦填进当前小节）：

- **顶部蓝色按钮 = 1~7 级**（罗马数字 `I`…`VII`），按当前调性 + 调式算级数
- **下面黑色按钮 = 该级数下的具体和弦**（如 VI 级 → `Am` / `Amaj7` / `A7` / `Aadd9` …）
- **一级分类筛选**：全部 / 三和弦 / 七和弦 / 六·加音 / 九和弦 / 扩展 / 挂留，
  点一下只剩该类，几十种和弦不用一页页翻
- **点弹窗以外的区域即关闭**，不用非得点中某个按钮
- 底部还有「清除该小节和弦」

和弦库共 **26 种性质**（`CHORD_QUALITIES`）：大三 / 小三 / 减三 / 增三、
大七 / 小七 / 属七 / 小大七 / 小七降五 / 减七 / 属七挂四、挂二 / 挂四、
大六 / 小六 / 加九 / 加十一 / 加十三、大九 / 小九 / 属九、
属七降九 / 属七升九 / 属七升五 / 属十一 / 属十三。

### 和弦音高亮提示（谱面 + 琴键）

每个小节指定的和弦，**谱面上对应的音块会盖一层半透明亮色遮罩**，
底部演奏条的琴键也跟着亮 —— 一眼看出「这一小节的和弦音是哪几个」，
不用盯着谱面一个个数音高。

谱面遮罩按**音块所在小节**的和弦算（每小节各管各的）；底部琴键按**当前目标小节**的和弦高亮
—— 改和弦、切小节、铺进行都会即时刷新。

### 铺进行：鼓组和其它音轨一起铺

「铺进行」不再只写和弦轨：

- **同时铺鼓组**（默认开）：用鼓型库里的鼓型把鼓组轨一起铺上
- **同时铺其它音轨**（默认开）：用当前模板把其它声部轨一起铺上
  （会覆盖这些轨该段的内容 —— 选项标题里写明了）
- 两个开关都放在「铺进行选项」里；铺完状态条会报告铺了哪些轨

铺完光标自动移到下一小节，连续铺进行时不用每次都去点标尺。

### 播放跟随：谱面整段翻页

编曲页播放时，播放头由音频时钟驱动（`app.js` 主循环 → `appArranger.onTick` →
`editor.followBeat`）。横向谱面（`scrollToBeat`）按**像素位置**翻页：

- 播放头出视窗左边界（循环回跳 / 倒退）或走到右缘 **90%** → 整段翻页
- 翻页后播放头落在视窗左侧 **12%** 处，谱面整体左移，随后继续在当页走动
- 翻页必须调 `render()`：只改 `scrollBeat` 不重画的话，画布停在旧的一页，
  播放头会在冻结的谱面上滑到右缘后消失/跳回，看着像「进度线在最后一段循环」

### 单轨编辑：试听只放正在编辑的那一轨

双击音轨进入单轨编辑。此模式下**试听默认只播放这一轨**：
编辑一条旋律时听整首伴奏，反而听不清自己刚改的那个音。

- 实现：`toSong({ onlyTrackIndex })` 在**返回的播放拷贝**里把其余轨 `muted = true`，
  sequencer 排程时直接跳过静音轨（`_fire` / 排程两处都判 `ev.track.muted`）
- **只动拷贝，不改编曲数据** —— 否则「临时静音」会被工程保存和曲谱导出带走
  （`App.song` 仍是完整版，只有传给 `sequencer.setSong` 的是隔离版）
- 编辑栏的「试听仅本轨」开关可关掉；播放中切换会从当前拍重排，进出单轨编辑同理
- 状态栏会显示「▶ 播放中（仅本轨）」，避免误以为别的轨坏了
- 鼓轨同样适用：编辑鼓组轨时只听到鼓

#### 单轨编辑的鼠标模式：框选 / 添加

编辑栏顶部的**「编辑模式」分段开关**决定鼠标在谱面上的行为（取代了原来的
「允许修改」勾选框 —— 那个勾选框只解决「要不要能改」，管不了「鼠标怎么用」）：

| 模式 | 空白处单击 | 空白处拖动 | 音块 | 选区 |
| --- | --- | --- | --- | --- |
| **框选**（默认） | 只清掉选区，**不加音** | 框选音块 | 点选 / 拖动 | 整组横/纵移动、Delete 删除 |
| **添加** | **直接加一个音块** | 框选音块 | 点选 / 拖动 | 整组横/纵移动、Delete 删除 |

- 默认「框选」：进单轨编辑先看清再改，手滑点一下不会凭空多出一个音
- 框选后拖动选区里的任意一块 → **整组一起走**（横向改拍位、纵向改音高，
  鼓轨改鼓位），纵向不跨轨，和弦不会被拆散
- **每次移动响的是这组的第一个音**（按时间最早的那个），拖到哪听到哪
- 总览视图始终只读：单击/双击只用来打开单轨编辑

#### 长按叠和弦

单轨编辑里**长按**（按住不动约 450ms）当前小节和弦里的一个音，会在它上方**自动叠一个和弦**：

- 只有**当前小节和弦里的音**能叠；不是和弦音会提示「这个音不在和弦里」
- 叠几个音由编辑栏的**「叠和弦」下拉**决定（**3 / 4 / 5 音**）
- 叠出来的音与原音**共享起始拍与时值**，叠完**整体选中** ——
  之后拖动就是**整组上下移**，拖边缘就是**整组拉长 / 缩短**
- 拖动过就不算长按（`drag.moved` 会取消计时器），不会误叠

#### 单轨音量：按轨增益，不动共享声部

轨头的音量滑条**写进这条轨自己的 `volume`**，发声时以「轨道音量 × 声部音量」计算增益：

- **不写回共享声部** —— 两条轨用同一个声部时，改一条轨的音量不会把另一条也顶掉
- 事件里带 `trackVol`，实时试听与离线渲染走同一条路径，导出的音量与听到的一致

#### 拖拽落点的音高试听（踩坑记录）

拖动音块时响的必须是**落点处的音高**，不是按下那一刻的旧音高：

- 按下时响一次当前音高（听到「抓起的是哪个音」）
- 拖动中音高变了就跟着响（同一个音高 140ms 内不重复触发，否则会变机关枪）
- **松手时再按落点音高响一次** —— 少了这一步，拖完了听着还是老音高，
  像是没拖上（`auditionDrop`）
- 滑音前块（`part === 'a'`）响的是滑音起点音高，不是音块本音

#### 拖拽音块的坐标基准（踩坑记录）

拖动时**位移永远相对「按下那一刻」的位置（`startX` + `origBeat`）**计算：

```js
newBeat = arr.quantize(d.origBeat + (x - d.startX) / this.pxPerBeat);
```

`origBeat` / `origPitch` 在这次拖拽内**绝不能改**（只允许更新「当前所在轨」）。
曾经写成每次 move 后 `d.origBeat = newBeat`，而 `dx` 始终是相对起点的总位移 →
每帧把位移重复叠加一次：拖 100px 会走到 1.5 倍位移，拖回去也回不到原位，
表现为「音块不跟手、落不住位」。`test-browser.js` 里有专门的用例守住这条（40/80/40px）。

### 小节删除时跨小节长音的处理

删除小节时，**跨越删除边界的音符按比例裁剪**，而不是整条删或原样保留：

| 情形 | 处理 |
|---|---|
| 完全落在删除区间 | 整条删除 |
| **与删除区间部分重叠** | **裁剪**（保住所剩的那一段） |
| 完全不重叠 | 保留 |

例：C4 从第 2 小节唱到第 3 小节（beat 5…9），删掉第 3 小节 → 裁成 beat 5…8（3 拍）。
若音符起点本身在删除区间内、但后半段还在，则整体后移填补空缺、时长不变。

### 载入谱面的健壮性

`importSong` 现在会：

- **保留文件里的 `role` / `drum` / `toneId` / `color`**（鼓轨不会被误判成合成器轨）
- 逐个音符做数值兜底：`beat`/`len`/`vel` 非法时给默认值，**`pitch` 缺失的音符直接丢弃**
- **不裁剪重叠** —— 交叠的音原样保留
- 轨内按 `beat` 稳定排序（渲染与命中依赖顺序）
- 脏数据（`null` 音符等）不会导致崩溃

## 十四、导入成谱（音频 → 鼓谱）

新页签「导入成谱」：**导入音频 → 分轨归类 → 自动生成鼓谱 → 写入编曲**。

### 轨结构：一个分轨文件一条轨
产出琴谱的 `tracks[]` 与导入的分轨文件**一一对应**，不按角色合并：

| 分轨角色 | 音轨名 | `role` / `toneId` | 音符来源 |
|---|---|---|---|
| 鼓 | 鼓组 | `drum` / `drumkit` | 起音检测 + 频谱分类 |
| 贝斯 | 贝斯 | `bass` / `bass` | YIN 单声部转录（30–480Hz） |
| 人声 | 人声 | `synth` / `vocalAh` | YIN 单声部转录（70–1000Hz） |
| 钢琴 / 吉他 / 其他 | 同名 | `synth` / `piano` · `acousticGuitar` · `warmPad` | **音符级转写**（见下） |
| `.mid` 文件 | MIDI 轨名 | 按 GM 音色映射 | 外部转写工具产物，直接量化 |

- **人声永远独占一轨**，不进和声轨
- 同角色多个文件 → 各自一轨，轨名自动加序号（`吉他`、`吉他 2`）
- 「整首混音」只当音频源（出鼓谱），不额外占一轨，避免与真分轨重复
- 写入编曲时按轨名匹配声部，匹配不到但内置音色/别名有同名（`人声`→`vocalAh`、`吉他`→`acousticGuitar`、`其他`/`和声`→`warmPad`）就自动建声部

### 复音转写（钢琴 / 吉他 / 其他）
不引神经网络、不引第三方库，纯 DSP：`STFT(4096/1024)` → 每个 MIDI 音高算**谐波显著性**（基频 + 2~5 次谐波加权）→ 逐帧归一化 → 迟滞出音符段，四道质检：

1. **邻音压制**：相邻半音里只留显著更强（1.35×）的那个，压掉强和弦的谱泄漏
2. **复音上限**：起音必须落在当帧最强 4 个音里（混响会把十几个音同时顶过阈值）
3. **基频校验**：基频处没有真谱峰（能量全来自高八度音的谐波）→ 判为八度假象丢掉
4. **碎片合并**：同音高间隔 < 0.25s 的段并回一个音

转不出来（< 12 个音）才退回原来的「和弦 pad」，保证谱面始终可用。

### 单声部音高跟踪（人声 / 贝斯）
YIN（CMNDF）出帧级基频后：

- **HPS 八度校验**：噪声大时 YIN 会落到真周期的 2 倍上（音高低八度），改检查更短周期（半周期/2/3）是否也是够低的谷
- **Viterbi 平滑**（替代原来的 3 帧中值）：每帧 1~2 个候选（主 + 八度备选），HMM 解码，发射代价 = `1 - conf`，转移代价 ∝ 跳幅、八度跳变重罚、静音↔有声也有代价 —— 连续孤立误判能被拉回来

### MIDI 导入（外部转写入口）
`src/midi.js` 是手写的 Standard MIDI File 解析器（format 0/1、running status、tempo 图、**拍号 meta（0x58）**、GM 音色映射、第 10 通道 → 鼓轨）。用法：

- 把 `.mid` / `.csv` 和音频一起拖进导入页（或点「＋ 导入音频 / 分轨」多选）
- 有音频时：MIDI 轨沿用本曲识别出的 BPM/拍号网格量化，**一个 MIDI 轨一条音轨**；MIDI 的时间原点映射到谱面第 0 拍（不跟音频小节相位走，否则前几拍会被当弱起丢掉）
- 只有 MIDI 没有音频时：用 MIDI 自带的速度/拍号建网格直接出谱（鼓/和弦/调性为空）
- 改 BPM / 拍号时 MIDI 轨同样只重排拍位、不丢音（复音，保留和弦叠放）

#### 速度与拍号：MIDI 里本来就是真值
| 场景 | 速度 | 拍号 |
|---|---|---|
| 只有 MIDI | `bpmDominant`（按 tick 跨度加权的主导速度，不是「第一条 tempo」） | `0x58` 拍号 meta（3/4、6/8 都认，内部按四分音符折算每小节拍数） |
| 音频 + MIDI | 音频估计；与 MIDI 差 <1% 时改用 MIDI 的整数栏（99.7 → 100），差 >5% 时提示 | 音频估计；MIDI 有音符轨且拍号不同 → 以 MIDI 为准并写日志 |

- **不能取第一条 tempo**：变速文件里第一条常常只覆盖开头一小节，后面几十小节全是另一个速度，取第一条会把整首谱按错速度画
- **多段变速**目前按主导速度建一条网格（日志会提示「N 段速度变化，后半段拍位会偏」），真正变速的曲子建议分段导入

#### 对齐音符：先聚类、再估偏移、最后量化
外部转写（Basic Pitch / Transkun / Melodyne）的 onset 有两类系统误差，直接「各自就近取整」会把节奏搞坏：

1. **和弦不齐**：同一和弦的几个音差几毫秒到几十毫秒 → 各自取整会被拆到相邻两格，谱面上是琶音、耳朵里也不对
   → 先按「同时性」聚类（≤20ms 归一个簇，簇内取中位时刻）
2. **整体平移**：转写延迟 / 导出前导空白 → 全部音符稳定偏半格，还会让开头几个音变成负拍被丢掉
   → 用全体 onset 相对网格的**中位残差**估一个全局偏移，整体平移掉（≥5ms 才动，避免把首音推到负拍）

网格不再死写 1/16，而是在 `1/16 → 1/8T → 1/16T → 1/32` 里按「几乎所有 onset 都贴格」挑第一个（粗网格能对上就不用更细的）；都对不上（真人演奏抖动大）时仍用 1/16 兜底，只有当更细的网格残差好 40% 以上才降级。自动判定不往 1/8 以上粗走 —— 编曲页要靠网格吸附，1/8 会把 16 分音符吸没。

> 置信度面板会显示「网格 1/16T · 平移 18ms」，让你看到「凭什么这样量化」。

#### 两个曾经的坑
- **分析完一直显示 30%**：`analyzeMidiOnly` 把进度设成 30% 后只调 `setProgress(null)` 隐藏进度条，**状态文字没复位**，于是永远停在「量化 MIDI … 30%」（其实早就成功了）。现在收尾会复位状态并写「已就绪 · BPM · 拍号 · 网格」；另外整段加了 `try/catch/finally`，抛错时 `busy` 会释放，不会卡死到只能刷新页面
- **写入编曲后 BPM 没更新**：`importIntoArranger` 只 `arr.fromJSON()`，编曲内部 `song.bpm` 已是新值（播放是对的），但顶栏输入框和 `App.song`/引擎还是旧速度。现在 fromJSON 之后统一 `syncAgControls() + pushTempo() + pushSig()`

**Basic Pitch 用户注意**（`*_basic_pitch.mid` + 同名 `.csv`）：

- basic-pitch 的 `.mid` 是「**一个 MIDI 通道只放同一个音高**」的结构 —— 一首 5 分钟的歌会写出 38~60 个轨。解析器识别出这个特征（单音高轨占比 ≥ 60% 且轨数 > 3）后**自动合并成一条轨**，否则导入页会出现几十条轨
- 音色/角色按**文件名**猜：`人声 → vocalAh`、`贝斯 → bass`、`钢琴 → piano`、`吉他 → acousticGuitar`、`其他 → warmPad`（和音频分轨共用同一套关键词）
- 同名 `.mid` + `.csv` 内容一致，**只取 `.mid`**，CSV 自动跳过（避免同一条轨出两遍）
- MIDI 与音频分轨是同一乐器时，日志会提示「两份转写内容重复，留精度高的那条」

> 建议的外部工具：Basic Pitch（Spotify，轻量、乐器无关）、Transkun v2（钢琴 SOTA）、Melodyne（人声手动校对）。它们的结果比本项目自研 DSP 准，但需要 Python/桌面环境；本项目的定位是「双击 `index.html` 就能用」，所以只做对齐不做替换。

### 分轨怎么来
页面里**不跑分离模型**（站点是双击 `index.html` 即可用的 `file://` 页面，Worker 被同源策略禁用，也装不下几十 MB 权重）。所以：

- 推荐先在 **UVR5 / Demucs / Spleeter** 里分好，把 stems 一起拖进来（文件名带 `drums`/`鼓`、`bass`/`贝斯`、`vocal`/`人声`、`piano`/`钢琴`、`guitar`/`吉他` 会自动归类，也可以在列表里手动改）
- 只给一个文件时按「整首混音」处理，能出谱但精度明显下降（低频互相干扰），日志里会提示
- 有鼓轨就用鼓轨分析；没有鼓轨才退回混音

### 分析链路（`src/analysis.js`，纯 JS 手写，无第三方库）
```
AudioBuffer → 单声道 @22050 → STFT(1024/hop256)
  → 每帧 8 段能量 + 谱通量/质心/平坦度
  → 三频段各自检测起音（低/中/高），再合成事件后按占比判定「这一下是谁」
  → 起音包络自相关 + 对数先验估速度（并优先选 90% 分内的快候选，避免系统性半速）
  → 相位搜索 + 最小二乘拟合拍点 → 重音投票定拍号/小节相位
  → 量化到 1/16 → 琴谱 JSON
```
几个关键设计（都有踩坑记录，别乱改）：

- **分频段检测起音**：真实鼓组里底鼓和闭镲总在同一拍响，用一条总包络挑峰会被「最短间隔」吃掉一个（实测 8 底鼓 + 8 军鼓全被当成镲）。合成事件后再按低/中/高频能量占比判是谁，于是「底鼓 + 闭镲」同刻能出两个音。
- **常数延迟自校准**：STFT 帧栅格会让起音整体偏十几毫秒，先拿全体事件对最近网格点的中位数残差当偏移扣掉，剩下的才是真抖动（否则对齐置信度永远偏低）。
- **半速/倍速**：自相关在 1/2/4 拍上都有峰，直接取最大值会把 100 BPM 判成 50 BPM。规则是「更快的候选只要分数在峰值 90% 以内就优先」，上限 190 BPM；仍有歧义时日志提示，界面给了 ×2 / ÷2 一键校正。

### 界面能做什么
- 波形 + 小节网格 + 按鼓位分行的鼓点预览，点画布选小节，试听从该小节开始
- BPM / 拍号 / 网格（1/8、1/16、1/32）**改了只重排网格，不重跑分析**（起音时刻是分析出来的真值）
- 置信度分项：速度 / 拍号 / 网格对齐 / 鼓分类，逐小节底色标出对齐差的段落
- 试听原音轨 / 试听谱面（从选中小节一路播到结尾，谱面 + 播放头自动跟随进度滚动）
- 谱面横轴缩放：`−` / `适配` / `＋` 按钮、Ctrl+滚轮（以光标为锚点）、Shift+滚轮平移；缩放后波形/和弦条/鼓点/网格共用同一套视窗换算
- 写入编曲（会整段替换，可用 Ctrl+Z 撤销）/ 导出 JSON（本地开发环境里有校验脚本 `validate_arrangement.py`，不随仓库分发）

### 已知边界
- **人声/贝斯是单声部转录**：和声叠唱、真假声切换会有八度错判，谱面要人工校一遍
- 与**底鼓同刻的闭镲**可能漏（底鼓很响时闭镲占比被压到阈值以下）—— 宁可少画不多画，谱面上假鼓点比漏掉的更烦人
- 复音钢琴/吉他这类**不承诺逐音**转写，P2 按「和弦 + 节奏型」输出
- 摇摆节奏、现场变速（rubato）、无鼓的抒情歌：网格可信度会明显下降，页面会如实标出来

## 十五、生成伴奏与导出

### 实时播放
序列器用 25ms 轮询 + 120ms 前瞻窗口把音符挂到音频时钟上，与硬件/DAW 的做法一致，不受主线程卡顿影响。

### 离线渲染
用 `OfflineAudioContext` 一次性渲染整首：
- 逐音符按绝对时间排程，结果与实时播放一致
- 渲染速度通常**快于**曲速（不是实时录制，是离线计算）
- 谱面结束后额外保留 2 秒混响/延迟尾
- 输出 WAV PCM 16bit 立体声 44.1kHz

**渲染期间必须关掉「发声节点回收」**（踩坑记录）：

引擎为了省资源，会在声音播完后定时把发声节点断开回收。离线渲染时这个回收定时器
会在渲染指针还没走到那个音时就断掉节点 —— 结果就是**导出的文件只有最后一段有声音**。
现在引擎带 `engine.offline` 标记，渲染期间关闭回收，渲染结束再统一释放。

### 分轨导出
把 JSON 中某条轨的 `part` 单独渲染即可得分轨文件，用于 DAW 混音。

### 内置示例谱（`songs/`）

| 文件 | 内容 |
|---|---|
| `01-dance-128.json` | 128 BPM 四踩舞曲，5 轨（底鼓/军鼓/踩镲/贝斯/和弦垫），4 小节循环 |
| `02-ballad-72.json` | 72 BPM 慢速抒情，3 轨（Pad/贝斯/主旋律），演示长时值与锁时长变调 |
| `00-empty-template.json` | 空模板 |

> 测试脚本只保留在本地开发环境，不随发布包分发（见 `.gitignore`）。

```bash
node test-core.js         # 255 项：纯逻辑（音高/解析/时序/WAV/WSOLA 音准/裁剪…）
node test-tone.js         #  64 项：内置音色信号完整性

node test-browser.js      # 浏览器端：UI 交互 + 真实音频行为（不打印项数，失败即非零退出）
```

`test-core` 覆盖：音高换算、乐谱解析与容错、时间轴、和弦识别、WAV 编解码往返、
**WSOLA 变调音准与时长锁定**、内置音色信号完整性、引擎参数、静音独奏、
序列器前瞻调度、离线渲染排程与 WAV 结构、序列化往返、格式识别、采样预处理、
**裁剪静音的三类素材**：

| 素材 | 断言 |
|---|---|
| 渐入 / 渐弱 | 识别为「无真静音区」，一帧都不裁 |
| 带底噪 | 底噪裁掉，有效信号完整保留 |
| 边界（全静音 / 极短 / 直流）| 不返回空 buffer |

WSOLA 音准用 Goertzel 能量扫描实测（先自检 440Hz 正弦测得 440.0Hz，再测变调结果），
不是拍脑袋的容差。

`test-browser` 的断言都是**行为验证**，不是「不报错」：

| 功能 | 关键断言 |
|---|---|
| **WAV 解码链路** | `BS.wav.decode` 存在、`Loader.wav` 不存在（命名空间）；`decodeFile` 端到端解码 File → 立体声 AudioBuffer，声道/时长/幅度全部正确 |
| 鼓组独立 | 鼓声部在 `engine.parts` 里为 **0**；12 个音高全部正确反查 drumId；每面鼓的 buffer 与自己音色的 buffer **同一对象**（音色不串） |
| 鼓组出声 | 独立分析器接鼓组通道，逐面鼓敲击，**12/12 都有信号** |
| **键位表（一字排开）** | 22 白键 + 15 黑键 = 37 键逐条核对；黑键正好落在白键缺口上；自检 0 错误；键位互不重复 |
| **键位发声** | 一字排开各区按键均有实际音频输出 |
| **编曲·单轨编辑** | 总览只读；双击进单轨编辑；「框选」模式点空白不加音；切「添加」模式可加音；右键平移视图；取消回滚、保存保留 |
| **编曲·和弦选择器** | 7 个级数（罗马数字）+ 分类筛选 + 该级数下的具体和弦；点弹窗以外区域即关闭 |
| **编曲·铺进行** | 和弦写进目标小节；鼓组轨与其它音轨一起铺；光标自动前进到下一小节 |
| **编曲·轨音量** | 轨音量写进轨道、**不写回共享声部**；事件带 `trackVol`，播放/渲染都按它算 |
| **编曲·渲染** | 从编曲直接渲染，渲染完可就地试听，信息标明来源 |

**测试环境要点**：

1. 必须 `Network.setCacheDisabled`，否则 `file://` 下 Chrome 缓存 CSS，
   改完样式重跑却看到旧效果。识别方法：改了三轮 CSS 后测量值**一模一样连小数都没变**。
2. 验证音频要用**独立分析器**接在通道输出上。主分析器 `getLevel().peak` 是异步峰值，
   敲完立刻读会拿到旧值；用主分析器 + `allNotesOff()` 会把刚敲的鼓也停掉，读数恒为 0。
3. 连着敲 12 面鼓时，前一面鼓的峰值会盖掉下一面 —— 必须逐面敲、逐面读。
